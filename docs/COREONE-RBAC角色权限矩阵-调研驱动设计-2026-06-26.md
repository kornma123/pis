# COREONE RBAC 角色—权限矩阵（调研驱动设计）

> **生成**: 2026-06-26 · **依据**: 深度调研（22 源 / 57 claim / 25 条 3 票对抗验证 → 22 确认 3 否决）
> **替代**: 旧 `FRS-03-角色管理.md`（仅描述现状、与代码多套口径矛盾，已弃用）
> **现行边界修订**: 2026-07-24 的 [ABC 域退役与兼容边界](prd/COREONE-ABC域退役与兼容边界-2026-07-24.md) 已覆盖旧 ABC 全成本产品决定。`abc_dashboard`、`slide_cost`、`profitability`、`abc_config`、`equipment`、`labor_times` 只可作为历史/兼容权限标识存在，不构成现行可分配能力，也不代表用户可达；`antibody_cost` 仅保留抗体台账、名称解析、别名、检测系统与材料标准成本等兼容能力。本文没有执行或声称后端存量角色权限、种子、表、字段或 helper 已迁移清除。
> **定位**: 面向独立/第三方病理诊断实验室（中国，免疫组化 IHC + 特殊染色）的耗材进销存 + BOM 材料标准成本与贡献毛利 RBAC 设计

---

## 0. 一句话结论

病理实验室在标准层面被切成**两条平行线**——**医疗诊断线**（病理医师：取材/镜检/诊断/报告签发，受资质门禁）与**技术处理线**（技术员：制片/染色/设备，**明确不诊断**）；**耗材/库存/采购/财务/材料成本**这条「运营线」在病理标准里没有岗位定义，须按**最小必要(least privilege)+ 职责分离(SoD)+ 角色围绕岗位职能**三原则推断。由此：**材料成本/贡献毛利可见性归财务与运营管理者，不归诊断医师**；**技术员归「技术+消耗」线（出库/消耗对账录入），不碰材料成本/贡献毛利**。

## 1. 真实岗位与职责（有据）

| 线 | 角色 | 核心职责 | 依据强度 |
|---|---|---|---|
| **诊断线** | 病理诊断医师 pathologist | 取材、镜检、病理诊断、报告**审核/签发**（签发权=中级+且≥3年）。**不碰运营/成本** | 高（CNAS-GL048、T/NAHIEM 98-2023） |
| **技术线** | 病理技术员 technician | 标本处理/脱水/包埋/制片/染色、设备使用维护、阳性对照选择(QC)。**明确不诊断** | 高（CNAS-GL048 附录A） |
| 诊断+技术 | 二者共担 QC | 室内质控 + 室间质评是医师与技术员各自必备能力（非独立成本岗） | 高（CNAS-GL048） |
| 运营线 | 标本接收登记 | 标本-申请单双核对、分配病理号（独立职能；本系统无此模块→N/A） | 高 |
| 运营线 | 库房管理 warehouse | 出入库/库位/盘点（**保管 custody** 须与**台账/对账 record-keeping** 分离） | 高（内控 SoD / COSO） |
| 运营线 | 采购 procurement | 采购订单/供应商（**需求提出**须与**供应商选择/定价**分离） | 高（《企业内部控制应用指引第7号》） |
| 运营线 | 财务/成本会计 finance | 材料标准成本/贡献毛利分析/BOM 标准成本（**材料成本/贡献毛利可见性归此线**） | 中（least-privilege/SoD 推断，见 §6 caveat） |
| 运营线 | **实验室主任/运营管理者 lab_director** | 全局总览（含材料成本/贡献毛利）+ 配置/审批；标准要求设技术负责人，区别于一线 bench | 高（角色存在）/ 中（成本可见性归属为推断） |

> ⚠️ 运营线（库房/采购/财务/主任）在病理标准里**无岗位定义**，是按通用内控 + RBAC 原则的**合理推断**，非病理文献直接给定。

## 2. 耗材/成本场景下「谁负责什么」（有据）

| 环节 | 负责角色 | 说明/依据 |
|---|---|---|
| ① 库存/库房（入出库/库位/盘点/调拨） | 库房管理（执行）；技术员（盘点执行/出库领用） | custody 与 record/对账分离 |
| ② 工作台试剂实际领用消耗（出库） | **技术员** | 技术线职责；非诊断医师 |
| ③ 消耗对账（实际 vs BOM 标准用量） | 技术员**录入实际** + 运营/管理层**核准**（**非诊断医师独立**） | 中（SPD 相邻先例 + SoD 推断） |
| ④ 采购与供应商 | 采购 | 需求/选择/定价三岗位分离 |
| ⑤ 材料标准成本/贡献毛利分析 | **财务/成本会计**（维护）+ 主任（查看） | BOM 标准用量×采购价→标准成本；盘点取实际→差异对账→周期调 BOM |
| ⑥ 报废/质控(QC) | 技术员（+医师 QC） | QC 归技术线+诊断线 |
| ⑦ 检测项目(panel) + BOM 配方 | 财务/运营维护标准用量；技术员/医师只读 | 两级 BOM 是标准成本基础 |

**与现状的核心纠正（粗体处）**：
- **退役能力**：`abc_dashboard`、`slide_cost`、`profitability`、`abc_config`、`equipment`、`labor_times` 不再对任何角色显示或分配；历史权限值不构成恢复入口或 API 的依据。
- **材料兼容能力**：`antibody_cost` 保留，仅服务逐抗体材料台账及其主线兼容面，不得借此恢复人工、设备折旧、场地或 ABC 全成本。
- **病理医生**：材料成本/贡献毛利/逐抗体材料成本一律 **—**。病理在「耗材+材料成本」系统里角色极小：只读检测项目/库存/BOM/预警 + QC。
- **技术员**：归「库存+消耗对账+QC」线（出库/盘点/消耗对账录入/报废 W），材料成本/贡献毛利 **—**。
- **财务**：材料成本/贡献毛利的**唯一 W 拥有者**。
- **运营总览（含材料成本/贡献毛利）**：归 `lab_director`（或 admin 暂代），不下放诊断/技术线。

## 5. 多角色账户处理（已确认的设计背景）

**现行合同**：`user_roles` 保存多角色，`primary_role` 只用于身份展示；鉴权、导航与仪表盘按目标环境角色权限并集驱动。实际能力以登录下发 capabilities 和后端 guard 为准，不以本文件的静态矩阵替代运行库。

**调研结论**：多角色在小型实验室确有发生；通用 SoD 要求**不相容职务必须分离**（采购需求 vs 选择定价；保管 vs 对账核准），CNAS 亦有「技术员与医师不相互兼职」信号。该方向已在 §8 确认，不再是待选择问题。

**已确认设计**：
1. **数据模型**：`users` 增 `roles`（多值 / 或 `user_roles` 关联表），保留一个 `primary_role` 作身份展示。
2. **能力合并（关键）**：前端 nav + 仪表盘 + 后端鉴权一律**按「该用户所有角色权限的并集」**驱动（capability-driven），而非单角色 switch——**天然兼容单/多角色**，并避免向无权角色发起必然被拒的请求。
3. **SoD 守卫**：对**不相容组合**（如 采购选择 + 财务核准、库房保管 + 对账核准）在分配时**告警/需审批**，小实验室可走「SoD 豁免审批 + 双人复核」。
4. **材料成本/贡献毛利可见性**：作为**可配置默认**（默认仅财务+主任可见），而非硬编码——因该结论是原则推断（§6）。

## 6. Caveats（诚实）

1. **「材料成本/贡献毛利可见性归财务而非诊断医师」缺中国病理实验室直接文献**——是 least-privilege(NIST AC-6/HIPAA) + SoD(COSO) + billing-vs-clinical 类比的**合理推断**。两条试图直接锚定的声明在对抗验证中被**否决(0-3)**。**建议落地为可配置默认，而非硬断言。**
2. **来源分层**：高=CNAS-GL048 / NHC 2009 指南 / 《企业内部控制应用指引第7号》；中=T/NAHIEM 98-2023（团体标准，最弱层级，且为建设标准非角色标准）；弱但有 NIST/COSO/HIPAA 背书=reanda/Censinet 等。
3. **场景外推**：消耗对账(SPD/定数包)与成本核算(检验科 BOM)实证均非「独立第三方病理 IHC/特染」专属；per-slide 抗体用量为合理外推，落地须用真实工作台数据校准。
4. **取材归属**：取材(grossing)按中国标准由**医师**承担（非技术员）。

## 7. 现行实现与存量数据的边界

1. **可分配面**：角色管理的创建、编辑、详情与列表只显示现行能力；六个退役 capability 不得因历史角色值重新出现在表格或表单中。
2. **用户可达面**：隐藏权限格子不等于完成退役；导航、Dashboard、可达路由和独立 API 仍须按 [ABC 域退役与兼容边界](prd/COREONE-ABC域退役与兼容边界-2026-07-24.md) 保持不可达、不可写或稳定退役语义。
3. **存量兼容面**：后端权限命名空间、初始种子、`roles.permissions`、表、字段、测试或 helper 仍可能含六个历史标识。这些数据只说明兼容债务或历史实现；本文未做数据库 migration、未清除存量权限，也不把其存在解释为当前产品能力。
4. **材料兼容面**：`antibody_cost` 继续可分配，但只覆盖抗体台账、名称解析、别名、检测系统等材料标准成本底座；旧全成本 preview、人工/设备/场地参数与校准面不因该权限保留而恢复。

## 8. 用户确认的落地决策（2026-06-26，逐行评审后锁定）

> **§8 记录用户确认的「初始种子值」，覆盖 §3 的原始推荐处；2026-07-24 后续退役决定再覆盖其中与六个退役 capability 冲突的部分。** 数据驱动 RBAC 仍允许管理员在现行能力目录内配置角色；历史/兼容权限键不得借“数据驱动”重新进入可分配面。

### 8.1 三项架构决策
1. **多角色：一步到位**——`user_roles` 关联表（多值）+ `primary_role`（身份展示）+ 鉴权/nav/仪表盘按**所有角色权限并集**驱动（capability-driven）+ 不相容组合 SoD 告警。
2. **材料成本/贡献毛利可见性：可配置默认**——默认仅 `finance`+`lab_director`(+admin) 可见，做成开关（非硬编码），因该结论是内控原则推断（§6 caveat）。
3. **数据驱动 RBAC（用户强调"后续配置灵活性"）**——矩阵存 DB（复用/扩展 `roles.permissions`），前端 nav + 后端鉴权 + 仪表盘 + 能力并集**全部读 DB 这份单一事实源**；管理员经「角色权限」页改格子即时生效，不改代码不发版。

### 8.2 §3 矩阵的确认改动（逐行评审 5 个判断点）
1. 病理 `库存`/`预警` 保留 **R**（不变）。
2. `BOM` → 主任、技术员 **W**（原仅 admin W）。
3. `检测项目` → 主任、技术员、病理、财务 **W**；采购 **—**；仓管 **—**。
4. `物料成本分析` → 采购 **R**（完整读，非"仅价格"）。
5. **已被后续决定覆盖**：原“设备管理分配给主任、技术员、财务/仓管”的初始种子决定不再是现行产品合同；`equipment` 与另外五个退役 capability 一律退出角色管理可分配面。
- 后续一致性边界：检测项目对病理/技术开放 W 不变；六个退役 capability 不对任何角色分配，`antibody_cost` 材料兼容权限保留给 admin(W)、lab_director(R)、finance(W)。

### 8.3 背景约束（用户原话）
- 决策基于**当前实验室现状（小公司、第三方）**；要求**为后续角色权限配置预留灵活性** → 故选数据驱动而非硬编码（见 8.1.3）。
