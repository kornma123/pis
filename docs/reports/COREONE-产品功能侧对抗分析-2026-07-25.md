## 1. 功能侧硬问题（按严重性排序）

### PF1 【伪造数字·最严重】物料成本分析页的"同期变化"列在真值为 null 时显示**随机数**

- **完整证据链（全部 CODE_CONFIRMED at master）**：
  - 导航 active：`/cost-analysis` 物料成本分析（route-registry.master.ts:163）；
  - 路由：`App.tsx:79` → `pages/report/CostAnalysis`；
  - 表格：`MaterialCostTable.tsx:75` —— `const changeValue = m.changeRate ?? Math.round(Math.random() * 30 - 15)`；
  - `ProjectCostTable.tsx:133` —— `const changeValue = p.changeRate ?? Math.round(Math.random() * 20 - 10)`。
- **后果**：后端按诚实口径返回 `changeRate: null`（LOC-030 已确认），前端却给每个物料/项目**编造一个 ±15%/±10% 的随机环比**，每次刷新数字还会变。这是碰钱展示面上的**伪造精确**，正是整个项目诚实体系（unknown≠0、算不出显"不可计算"）要杀的东西——而且它藏在"已经修过"的叙事里。
- **更尖锐的矛盾（两份权威文档都声称它不存在）**：
  - PRD v1.6 §4.1 诚实缺口行：「成本报表当前把同期变化保持为 `null/不可计算`」——**与代码事实相反**；
  - 本地 Issue 指导 LOC-030：「Mac C8 的'前端 Math.random 兜底'在 d144 未复现……因此不得按旧触发开 bug」——**校准结论错误**，随机兜底就在当前 master。
  - 也就是说：文档不仅没防住问题，还给了"已确认无此问题"的假凭证。#31（LOC-030，OPEN）的触发前提需要更正。
- **减法修复**（不加功能）：删除两处 `?? Math.round(...)` 兜底，`null` 一律渲染"不可计算"；同步更正 #31 正文与 PRD §4.1 的描述。这是行级修改，但按契约仍须走 Issue + preflight（可并入 #31 重述后派工）。
- **Root 裁决（2026-07-25）**：✅ **已采纳**——确认两处 `Math.random()` fallback 仍在活代码；Issue #31 已更新为 **P1 / 阻断上线**，合同=unknown fail-closed、合法 0 保留、不得猜跨期公式。

### PF3 【命名/定位混乱】导航里仍有一个叫"消耗对账"的页，而 PRD 说消耗对账域"整域已删"
